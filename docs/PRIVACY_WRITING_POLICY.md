# Privacyページ文章方針

## 1. 適用範囲と位置付け

委託販売ノートのユーザー向けPrivacyページの新規作成・修正・翻訳・公開に適用します。日本語・英語、正規URL・別URL、今後追加する同アプリのPrivacy関連ページ、見出し・リンク文字列・アクセシビリティ用説明を含みます。特定バージョンに限定しません。

N1-S47改訂版のオーナー確定方針を正式なルールとして保存した文書です。文章方針の採用承認は、Privacy本文やWeb公開の承認とは別です。解決済みの同意方式や申告判断を、この方針だけで再審査しません。

## 2. サービス名より役割を説明する

表示本文では、PostHog、RevenueCat、Cloudflareなど開発者向けのサービス名・事業者名を原則記載しません。名前だけでは一般利用者に役割が伝わらないためです。実際の役割と取扱いを、平易な言葉で具体的に説明します。

- 「利用状況の分析に使う外部サービス」
- 「アンケート回答を受け付ける外部サービス」
- 「Proの購入状態を確認するサービス」
- 「Webサイトの配信やアクセス状況の確認に使う仕組み」

名称を置き換えても、実際の外部送信や第三者による処理を隠してはいけません。Apple・App Storeなど、決済方法の説明に必要な一般向け名称は、正確さを損なう形で機械的に削除しません。提供者であるHiro App Works、アプリ名、お問い合わせ先も維持します。

法令・審査要件などから特定の事業者名が必要と判断した場合は、根拠と該当箇所をオーナーへ報告し、承認を求めます。独断で例外を増やしません。

技術記録・内部監査・ソースコードでは正式名称を使って構いません。HTMLコメント、計測スクリプト、外部リンクURL等は表示本文と区別します。名称を消す目的だけで、必要な処理やリンクを削除・破壊しません。

## 3. 落ち着いた誠実な説明

- 一般利用者が、何が端末内に保存され、何が外部へ送られるか理解できる文章にします。
- 商品・写真・売上等の業務データと利用ログを明確に区別します。
- 設定で選べる範囲、停止できる通信と停止しない通信を具体的に示します。
- 不必要に警告的・防御的な表現、過度な免責、技術的な事情の押し付けを避けます。
- 安心感を優先しても、事実を隠したり、根拠のない安全性を保証したりしません。

## 4. 自然な日本語と英語

日本語は丁寧で落ち着いた「です・ます調」に統一します。不自然な直訳、英語の語順、不要なカタカナや専門用語を避け、難しい語は意味を保って言い換えます。一文を長くしすぎず、同じ説明を複数箇所で繰り返しません。

英語も英語圏の一般利用者が自然に理解できる平易な文章にします。逐語訳より意味の一致を優先します。ただし、条件・例外・法的に必要な意味を削りません。

## 5. 必ず保つ情報開示

実際のアプリ挙動と承認済み証拠に基づき、必要な範囲で次を説明します。

1. 取り扱う情報の種類と利用目的
2. 送信される条件、利用者の明示操作、任意性
3. 利用者が停止・選択できる範囲と設定の保持
4. 外部サービスへの送信と第三者による処理
5. 保存地域・保存期間、その期間が意味する範囲
6. 問い合わせ・削除依頼への対応と、対象の特定等の限界
7. 必要な例外・制限（送信停止と過去情報の削除の違い等）

設定変更が過去データの削除を意味する、識別子が完全匿名を保証するなど、証拠のない説明はしません。通信設定と実際の観測、実装とサーバー配信の状態を区別します。

## 6. 禁止表現と推奨例

| 避ける表現 | 実態が一致する場合の説明例 |
| --- | --- |
| 個人情報を一切収集しません | 業務データは端末内に保存します。利用状況の分析には、操作の種類やアプリの版などを外部へ送信します。 |
| 完全に匿名です | 氏名やメールアドレスに基づかない識別子を使い、同じアプリでの利用を把握します。 |
| 外部へ情報を送信しません | 業務データを利用ログとして送信しません。購入確認や任意アンケートのための通信は別に行います。 |
| 必ず完全削除できます | 確認できる情報に基づいて削除のご相談に対応します。対象記録を特定できない場合は、その範囲を説明します。 |
| サービス名だけを挙げる | 情報を受け取るサービスの役割と、情報の種類・目的・送信条件を説明します。 |

これらは文章例であり、新しい製品仕様・収集や削除の保証を承認するものではありません。

## 7. 日英翻訳と品質の確認基準

- 見出しと段落の対応を確認し、情報の種類・目的・条件・例外・任意性・設定保持・送信先の地域・保存期間・削除の限界を両言語で照合します。
- 英語原文の日本語訳もオーナーへ提示し、意味の差があれば明示します。
- 正規URLと別URLの本文が同じ意味・内容であることを確認します。
- 可視本文、リンク文字列、画像代替文、アクセシビリティ用説明に不要なサービス名が残らないか確認します。技術要素は別に扱います。
- 初めて読む利用者の視点で、読みやすさ、繰り返し、不必要な不安、情報を隠しているように見える表現を確認します。
- 実表示、リンク、言語切替、モバイル・デスクトップ表示と既存Web機能を確認します。

現在の公開文を取得したうえで、変更前後の全文、理由、追加・削除・変更なしをセクションごとに提示します。英語の変更前後には日本語訳を付けます。完成した日本語全文・英語全文・英語の日本語訳全文を、条件や例外を省かず確認できる状態にします。

対象ファイル、commit、SHA-256と未解決事項を記録し、オーナーの全文承認を待ちます。文章方針の承認、本文の承認、公開操作の承認を混同しません。実際の公開日が決まるまで公開更新日をローカル修正日に変更しません。

公開・deploy・main統合・App Review提出等は、それぞれ当該タスクの明示承認に従います。この文書自体はそれらを許可しません。
